# React 原型整体视觉与布局重构规范

日期：2026-09-04  
适用范围：根目录 React 原型的 AppShell、34 个页面、27 个交互状态  
目标：从“高保真静态后台模板”升级为“安静、可信、清晰、可行动的机会情报工作台”

## 1. 视觉诊断

当前页面并不粗糙，但美感主要来自整齐和统一，还没有建立成熟产品需要的注意力秩序。

### 1.1 所有模块看起来同样重要

P01 的六个 KPI、机会、信号、告警、趋势、研究和系统状态几乎都使用相同白底卡片、边框和圆角。用户看到的是一个整齐的网格，而不是“今天应该先处理什么”。

P09、P10、P24–P30 又复用同一种卡片语言，导致仪表盘、实体详情、设置和诊断页面在视觉上缺少类型差异。功能不同，页面气质却相同。

### 1.2 边框承担了过多布局工作

当前大多数区域都依赖 `1px #e2e8f0` 边框封装。边框很多，但层级仍然弱，因为每个盒子的对比度、圆角和内边距都相近。最终效果是“卡片很多、重点很少”。

### 1.3 色彩丰富，但语义不稳定

蓝、紫、绿、黄、红、青被同时用于图标背景、标签、趋势和状态。颜色产生了热闹感，却没有稳定回答：什么是品牌动作、什么是成功、什么是风险、什么只是分类。

### 1.4 空间是均匀的，不是有节奏的

卡片内部普遍较松，章节之间却没有明显的 24/32/48px 节奏变化。页面标题、筛选、摘要和主体像连续组件堆叠，而不是具有“开场—判断—行动—证据”的阅读流程。

### 1.5 页面过度横向铺展

工作台和列表可以使用宽屏，但长摘要、研究结论、设置表单和日志说明不应横跨整个内容区。缺少阅读宽度限制会让页面显得空而散，并降低文本理解速度。

### 1.6 交互反馈偏“演示型”

大量按钮点击后只显示 toast；hover、selected、loading、optimistic、disabled、permission denied、partial data 等状态没有形成稳定视觉语言。静态截图完整，真实使用时的可信感不足。

## 2. 目标视觉语言

关键词：`Calm Intelligence / Evidence First / Actionable / Dense but Breathable`。

- **安静**：减少彩色装饰、阴影和无意义盒子，让数据和结论成为视觉主体。
- **可信**：明确证据、时间、来源、状态和数据新鲜度；避免“炫但不确定”的视觉表达。
- **清晰**：每屏一个主重心，章节有稳定对齐线，操作有明确主次。
- **可行动**：页面不仅展示信息，还明确告诉用户下一步是什么、为什么。
- **高密度但可呼吸**：通过列宽、分组、渐进展开和信息优先级提升密度，而不是缩小字号。

这不是 BI 大屏，也不是通用 Admin 模板。产品视觉应更接近研究员的“情报桌面”：结论突出、证据可追溯、风险克制但醒目。

## 3. 全局构图系统

### 3.1 AppShell

| 属性 | 桌面建议 | 说明 |
|---|---:|---|
| 展开侧栏 | 208–216px | 176px 显得像压缩后台；增加品牌和导航呼吸感 |
| 收起侧栏 | 64px | 只保留图标和 tooltip |
| 顶栏 | 64px | 与 40px 搜索/账户控件形成稳定垂直节奏 |
| 页面水平 gutter | 32px；窄屏 24/16px | 不同页面不得自行发明 |
| 最大工作区 | 1440px | 超宽屏居中；图谱/日志可声明 full-bleed |
| 页面标题区 | 72–88px | breadcrumb、标题、说明和操作组成完整开场 |

侧栏使用接近白色或轻微冷灰，不再通过大量图标颜色吸引注意。当前模块用背景块 + 左侧 2–3px 品牌色标记；只使用一个 active signal。

顶栏搜索是全局主工具，应有 360–480px 可用宽度。领域切换、通知、帮助和头像保持紧凑，不与页面主操作竞争。

### 3.2 页面布局类型

每个页面必须归入一种模板，禁止逐页自由拼装。

#### A. 分诊工作台

适用：P01。

```text
┌──────────────────── 页面标题 / 日期 / 刷新状态 ────────────────────┐
├──────────────────── 今日简报：主结论 + 主行动 ─────────────────────┤
│ 优先机会与重要信号（8列）              │ 待处理事项（4列）         │
│ 趋势变化与原因（8列）                  │ 数据/系统可信度（4列）    │
└───────────────────────────────────────────────────────────────────┘
```

首屏不再先放六张同权 KPI 卡。保留 3–4 个紧凑指标作为今日简报的一部分，真正异常的指标进入右侧“待处理事项”。

#### B. 列表工作台

适用：P02、P04、P05、P08、P14、P17、P19、P21–P23、P25、P29、P31。

```text
页面标题 + 1个主操作 + overflow
保存视图 / FilterBar
┌───────────────────────────────┬────────────────────┐
│ 主列表（>=1440 时 8列）       │ 预览（4列，可关闭）│
└───────────────────────────────┴────────────────────┘
分页 / 批量状态
```

1280px 以下不固定展示预览栏，改为 Drawer；否则主列表标题列会被压缩。筛选条件超过一行时，“常用筛选”保留首行，其余进入展开区域。

#### C. 实体详情

适用：P03、P09、P12、P15、P18、P20。

```text
EntityHeader：名称 / 状态 / 关键元数据 / 主操作 / 更多
Tab：概览 / 证据 / 历史 / 运行...
┌────────────────────────────────────┬─────────────────┐
│ 主叙事与证据（8列）                │ 状态摘要（4列） │
│ 活动或时间线                       │ 负责人/下一步   │
└────────────────────────────────────┴─────────────────┘
```

EntityHeader 只出现一次。评分、状态、负责人和最近更新时间不要在卡片、侧栏、Tab 中重复。右栏可 sticky，但正文阅读列控制在 640–760px。

#### D. 分析画布

适用：P06、P07、P10、P13、P16、P30。

```text
结论条：发生了什么 / 为什么重要 / 数据新鲜度
控制条：对象、时间窗、对比、导出
主图或主分析（8–9列） | 解释/异常/证据（3–4列）
明细数据表 / 方法说明
```

图表不是装饰。每个图必须带一句结论、时间窗、单位、数据来源和可访问的数据表替代视图。

#### E. 设置与治理

适用：P24、P26–P28。

```text
设置标题
┌──────────────┬──────────────────────────────────────┐
│ 二级导航     │ 单一内容列，最大宽度 760–880px       │
│ 224px        │ Section + divider，不堆卡片          │
└──────────────┴──────────────────────────────────────┘
```

设置不是 dashboard。一个页面只处理一个设置主题；普通表单 section 使用标题和分隔线，不需要每段都加卡片。危险区独立放在页面末尾，只有不可逆动作使用红色。

#### F. 认证与系统状态

适用：P32–P34。

登录页保留品牌双栏，但调整为约 45/55，表单区域最大宽度 440px。403/404 使用更轻的单焦点页面，不复制完整 dashboard 视觉。

## 4. 视觉层级规则

### 4.1 每屏只允许一个主重心

优先级顺序：

1. 页面主结论或当前对象。
2. 当前风险/异常或需要处理的任务。
3. 支撑证据与趋势。
4. 系统元数据和辅助入口。

如果首屏同时有六个大数字、三个粗标题和四个蓝色按钮，等于没有重点。

### 4.2 操作层级

- 每个 PageHeader/EntityHeader 最多一个 Primary action。
- 最多两个可见 Secondary action，其余进入“更多”。
- 危险动作不出现在常规主操作组，必须进入独立 danger section 或二次确认。
- 表格行操作默认一个常用动作 + overflow；不要同时放多个低对比图标。
- 保存只在存在 dirty state 时成为主按钮；只读页面不显示假的编辑入口。

### 4.3 内容层级

- 页面标题回答“在哪里”。
- 页面副标题回答“这个页面帮助做什么”，不重复标题。
- Section title 回答“这组信息是什么”。
- 卡片标题回答“它的判断或对象是什么”，避免统一使用模糊名词。
- 关键结论使用完整句子，例如“企业 AI 机会评分升至 85，主要由采购信号驱动”，而不是只展示“85”。

## 5. 表面、边框、圆角与阴影

只使用三层表面：

| 层级 | 用途 | 建议 |
|---|---|---|
| Page | 全局背景 | `#F6F8FB` 或接近色 |
| Surface | 表格、主内容、表单 | 白色；必要时 1px 中性边框 |
| Raised | Drawer、Modal、浮层 | 白色 + 明确阴影 |

规则：

- 同一页面不要给每个 section 都加外框。通过 24–32px 间距、标题和 divider 分组。
- 卡片圆角统一 10–12px；输入和按钮 8px；小标签使用 full radius。
- 常规卡片默认无阴影或仅极轻 shadow；阴影主要保留给浮层、拖拽、悬停提升。
- 禁止卡片嵌套卡片超过一层。
- 数据表可以是一个 Surface，但表格每行不再额外卡片化。

## 6. 色彩系统

### 6.1 品牌色与语义色分离

建议基础色：

| Token | 建议 | 用途 |
|---|---|---|
| Brand 600 | `#2563EB` 或更稳重的 `#1D4ED8` | 主操作、当前导航、关键链接 |
| Brand 50 | `#EFF6FF` | 选中背景，不做大面积装饰 |
| Text primary | `#0F172A` | 标题、正文主信息 |
| Text secondary | `#475569` | 说明和非主信息 |
| Text muted | 不浅于 `#64748B` | 时间、单位、辅助元数据 |
| Page | `#F6F8FB` | 页面背景 |
| Border | `#E2E8F0` | 必要边界 |

语义色仅表达明确状态：

- Green：成功、健康、已完成。
- Amber：需要注意、等待、可能恶化。
- Red：失败、高风险、不可逆操作。
- Blue：信息和产品主动作。
- Purple/Cyan：仅在确有稳定业务分类时使用，不能随机装饰不同卡片。

一条信息最多使用一个主语义色。状态 Badge 使用浅底 + 深文字，必须同时显示文本或图标，不只靠颜色。

### 6.2 深色品牌区

P32 的深蓝品牌面可以保留，并成为品牌识别的主要场景。登录后的工作区保持浅色与克制，不把深色大面积复制到业务页面，以免变成“监控大屏”。

## 7. 排版与空间节奏

排版标准沿用 `REACT_PROTOTYPE_GLOBAL_REVIEW.md` 的语义字号。视觉实现还需遵循：

- 数字使用 tabular numerals；金额、百分比和单位分层，不把单位做成 10px。
- 中文正文 line-height 1.55–1.7；表格可压缩到 1.4–1.5。
- 长段正文宽度 640–760px；摘要最多 2–3 行，提供展开。
- 标题不得通过一味加粗体现层级；字号、留白和位置优先。

建议空间 token：`4, 8, 12, 16, 24, 32, 48, 64`。

- 控件内部：8/12/16。
- 关联元素：8–12。
- 卡片内部：20–24。
- Section 间距：32。
- 页面大章节：48。

## 8. 组件视觉规范

### 8.1 KPI/Metric

- 不默认使用卡片。可在摘要条中以 divider 分隔。
- 必须包含：指标名、值、单位/口径、变化、时间窗。
- 变化颜色只有在业务上明确好坏时使用；“下降”不一定是红色。
- 工作台首屏最多 4 个关键 metric，其余进入展开或对应模块。

### 8.2 Table

- Header 高 40–44px，正文行默认 52–60px；密度模式可到 44px，但字号仍不低于 14px。
- 标题列有明确最小宽度；描述不在窄列中逐字换行，使用 1–2 行截断。
- 数值右对齐，状态居中或左对齐保持一致，操作固定最右。
- Hover 只轻微改变背景；selected 使用品牌浅色背景 + 左边标记。
- 空态、加载 skeleton、部分失败、权限不足分别设计。

### 8.3 Card

- Card 必须表达一个完整对象或判断，不只是为了把内容框起来。
- Header、body、footer 对齐；可点击卡片整体提供 hover 和键盘 focus。
- 同一栅格卡片高度相等，但不为追求整齐塞入无意义空白。

### 8.4 Badge

- Badge 用于短状态/分类，不承载句子。
- 状态 badge 和分类 tag 视觉不同：状态有语义色，分类使用中性底或弱品牌色。
- 同一行最多展示 2 个 tag，其余显示 `+N`。

### 8.5 Drawer/Modal

- Drawer：上下文编辑、详情预览；宽度 480/640 两档。
- Modal：短确认、单一任务；不承载长表单或完整详情。
- Footer 主按钮固定右侧；危险确认要求明确对象名和后果。
- 背景遮罩、焦点、Escape、滚动锁和 loading 状态一致。

### 8.6 Charts

- 主数据色使用品牌蓝，比较序列使用中性灰；异常才使用红/橙。
- 网格线弱化，坐标文字不小于 12px。
- 不使用装饰性圆环图重复可以直接读出的单一百分比。
- Tooltip 包含数值、时间、口径与来源；键盘用户有数据表替代。
- 颜色系列不超过 5 个，超出后改筛选或 small multiples。

### 8.7 Empty/Error/Loading

- Empty：解释为什么为空 + 一个明确下一步，不使用成功 toast 代替。
- Error：显示可读原因、request ID、是否可重试；技术详情折叠。
- Partial：保留可用内容，在模块顶部显示局部异常，不整页报错。
- Loading：页面骨架匹配最终布局，避免全屏 spinner。

## 9. 核心页面重排

### P01 今日雷达

当前问题：首屏 6 个同权 KPI，下面 6 个同权卡片，像 BI dashboard，缺少今日判断。

重排：

1. 标题右侧显示数据更新时间与刷新，不再把刷新藏在系统状态中。
2. 顶部改为“今日简报”：一句主结论、3–4 个关键 metric、一个主动作。
3. 主体左侧优先机会与重要信号，按影响/新鲜度排序并说明理由。
4. 右侧合并“待处理告警 + 数据可信度”，只展示需要行动的异常。
5. 趋势图增加一句解释；研究进度下沉或与相关机会合并。

### P02 情报列表

当前问题：概念正确，但 1280px 的表格和固定预览互相争夺宽度；筛选和视图 chip 占两行但层级相近。

重排：

1. 搜索占主宽，来源/标签/时间为常用筛选，高级筛选折叠。
2. “我的视图”放入单独 saved-view 控件，不与业务筛选混排。
3. `>=1440` 展示 8/4 主从布局；小于 1440 点击行打开 Drawer。
4. 标题列至少 320px；来源 120px、时间 112px、置信度 88px、操作 56px。
5. 预览首屏只展示结论、来源、关键信号和主动作；实体与原文放到展开区。

### P09 机会详情

当前问题：四个顶部 metric 同权；四个头部操作同权；摘要、时间线、当前状态和下一步彼此割裂。

重排：

1. EntityHeader 内合并评分、状态、领域、负责人和更新时间。
2. “启动研究”作为唯一主动作；修改状态/负责人为 secondary，结构化分析进入 Tab 或更多菜单。
3. 概览首段直接显示机会判断与评分驱动，而不是四张 KPI 卡。
4. 证据时间线成为主列；状态与下一步合并为右侧行动面板。
5. 市场规模、竞争与壁垒进入结构化分析 Tab，不在概览重复。

### P24 工作区设置

当前问题：设置内容被做成 dashboard 卡片网格；危险区域包含导出、清理、重置、删除四个不同风险等级的动作。

重排：

1. 使用 224px 二级导航 + 760–880px 单内容列。
2. 当前路由只展示一个设置主题，其他主题通过路由切换，不同主题不同时铺满页面。
3. 导出属于“数据管理”，清理属于“保留策略”，重置属于“配置”，只有删除属于危险区域。
4. 所有设置行使用 label、说明、control 的稳定三列/两列对齐。
5. 页面底部 sticky save bar 只在存在未保存修改时出现。

### P32 登录

当前问题：是当前视觉完成度最高的页面，但左侧品牌区占比略大，营销文字和功能说明对比偏低，右侧表单显得较小。

重排：

1. 比例调整为约 45/55，表单宽度 400–440px。
2. 品牌主文案保留，四条能力缩减为三条，增加对比度。
3. 表单标题、label、输入和帮助链接统一到新字号系统。
4. MFA、SSO、密码恢复使用真实状态，不用同一表单中模拟全部流程。

## 10. 动效与微交互

- 基础反馈 120–180ms；Drawer/Modal 180–240ms；不要使用全局 `transition: all`。
- Hover 只改变背景、边框或轻微 elevation，禁止页面元素无意义漂移。
- 列表选择、Tab 和筛选变化保持布局稳定，避免内容整体跳动。
- 成功 toast 只用于已完成且不需要继续处理的动作；异步任务使用持久状态条或任务入口。
- 危险动作的确认动画和颜色应克制，重点是后果文本与对象识别。

## 11. 实施顺序

1. **视觉基线**：设计 token、字体、颜色、空间、surface、focus、motion。
2. **页面骨架**：AppShell + 六类页面模板 + 响应式断点。
3. **公共组件**：Header、EntityHeader、Table、FilterBar、Metric、Card、Badge、Drawer、Modal、状态组件。
4. **样板页**：先重做 P01、P02、P09、P24、P32，并完成设计评审。
5. **批量迁移**：按页面类型迁移其余页面，不按页面编号逐个自由实现。
6. **视觉 QA**：五档视口、真实长文本、空态/错误/部分失败、键盘、对比度、截图回归。

样板页通过后再批量迁移，可以避免 34 个页面重复返工。

## 12. 视觉验收清单

- 首屏是否有且只有一个明确视觉重心？
- 用户 5 秒内能否理解主要结论、风险和下一步？
- 是否存在为了布局而创建、但没有独立语义的卡片？
