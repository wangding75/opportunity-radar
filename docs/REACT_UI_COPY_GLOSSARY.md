# React UI 文案规范

## 写作原则

- 标题描述用户所在位置；副标题说明用户能做出的判断或动作，不能重复标题。
- 结论用完整句，包含对象、变化/状态和理由；数字要有单位、时间窗或口径。
- 一个按钮只表达一个动作，优先使用动词加对象，例如“启动研究”“保存规则”。
- 不把请求已接收、任务运行中和业务已完成写成同一个“成功”。

## 状态词汇

| 场景 | 使用 | 禁止 |
|---|---|---|
| 请求成功且已回读 | “已保存”“已更新” | “操作成功” |
| 已提交异步任务 | “研究任务已创建，正在排队” | “研究已完成” |
| 外部投递排队 | “通知已加入投递队列” | “已通知团队” |
| 可重试失败 | “保存失败，请重试。请求 ID：…” | “系统异常” |
| 无权限 | “你没有编辑此规则的权限” | “访问失败” |
| 空数据 | “尚无符合当前筛选条件的情报” | “暂无数据” |

## 页面句式

- 今日雷达：`过去 24 小时发现 8 个机会，其中 3 个需要优先研判。`
- 图表结论：`企业 AI 信号较上周上升 24%，主要来自采购与融资事件。`
- 风险提示：`3 个来源连续采集失败，可能影响本周趋势完整性。`
- 保存前：`你有未保存的修改。`
- 失败后：`未能更新负责人；原有分配未改变。`
