# 后端接口缺口处理规则

## 核心规则

1. UI 开发不得因为后端接口缺失而整体 BLOCK。
2. 每次实现前先核对当前页面读取/写入动作对应的真实后端能力。
3. 若接口存在且语义等价：登记为 `MATCHED`，接真实接口。
4. 若接口存在但字段/状态语义不一致：登记为 `CONTRACT_MISMATCH`，UI 采用只读、禁用或隐藏，不猜字段、不伪造成功。
5. 若后端存在能力但没有安全 API 暴露：登记为 `CAPABILITY_NOT_EXPOSED`，本 UI 包不临时新增后端接口。
6. 若能力确实不存在：登记为 `DEFERRED_UNAVAILABLE`。
7. 所有缺口统一写入 `001_BACKEND_INTERFACE_GAPS.csv`，写明证据、影响 UI、降级策略。
8. 缺口不得阻断其它可用页面、路由、测试、Docker 启动或最终 UI 验收。
9. 禁止 fake success：不得用本地状态假装服务端已保存；不得弹“保存成功”掩盖接口缺失。
10. 后端能力修复另立后续任务，不混入本轮 R04 UI 重建提交。

## UI 降级优先级

`隐藏不成立的动作` > `明确只读` > `禁用并解释原因` > `占位状态`

能正常读取的数据必须继续正常展示。
