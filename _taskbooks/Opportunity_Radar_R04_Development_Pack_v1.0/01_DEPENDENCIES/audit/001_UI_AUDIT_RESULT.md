## 审核原则

1. 用户可见业务文案优先简体中文；英文仅允许品牌、ID、URL、版本、技术日志/字段。
2. 统一 AppShell：固定一级导航、顶栏、PageHeader/EntityHeader，拒绝明显深色侧栏或结构漂移候选。
3. 详情页 Tab 必须对应真实 UI；列表 → 详情 → 证据/来源/运行/研究 → 返回路径要能形成浏览与追溯闭环。
4. 未确认后端写接口的能力不允许用可执行主按钮伪造成功。
5. 同一状态多个候选时，优先信息架构清晰、可读、闭环入口完整、中文化更好、外壳更一致的版本。
6. 明显截断、纵向错误、主体缩小或覆盖主内容的候选淘汰。

## 闭环审核

### PASS
- 工作台 → 机会 → 机会详情 → 证据 → 情报/数据源 → 研究结果 → 返回机会
- 最新情报 → 情报详情 → 原始证据/关系/处理过程 → 数据源/运行/分析队列
- 研究结果列表 → 结果详情 → 证据/方法/活动记录 → 任务/结构化分析/机会
- 监控计划 → 计划详情 → 数据源 → 运行记录 → 运行详情 → 日志/产出/关联对象
- 告警 → 规则说明/关联运行/来源 → 对应详情
- 用户与角色/系统设置 → 审计日志/系统诊断
- 搜索、通知、帮助、登录帮助、403、404 均有落点

### 后端能力边界
本包只证明 UI 信息架构与浏览/研判/追溯闭环。机会状态变更、研究生成、研究任务推进、监控计划启停/立即运行、运行重试、告警读状态/关闭、用户角色写操作、通知/集成配置写操作等仍应按后端真实能力决定；UI 中不得伪造。
